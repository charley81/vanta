# Issue #48 — Published Editorial delivery evidence

Scope: `CONTENT-004`, `ARCH-005`, `ARCH-006`, and `ARCH-007`, with supporting validation for `CONTENT-001` and `CONTENT-003`.

## Composition contract report

Production Home, Product, Synth, metadata, and root-layout code now read through [`public-content.server.ts`](../../../src/editorial/public-content.server.ts). The module calls the isolated published Sanity adapter with the fixed GROQ projections, validates the projected values, and only then composes them with code-owned Product truth and Catalog values.

Focused tests demonstrate that:

- all four required singletons are read and validated;
- Product identity and `$2,499 USD` continue to come from code when Editorial prose comes from the adapter;
- absent singletons, HTML/embedded links, malformed fields, prohibited claims, and cross-owner fields reject instead of being substituted;
- the Sanity adapter selects only a fixed projection and the `published` perspective;
- Server Components call the server module directly rather than an application Route Handler.

## Cache architecture and resilience report

Each singleton has its own async `use cache` scope, literal `cacheLife("max")`, and exact `sanity:document:<singleton>` tag. The production build reports the expected 30-day revalidation and one-year expiry generated by the `max` profile.

The design deliberately relies on Next.js stale-while-revalidate behavior rather than an application `Map` or another process-local last-value cache. A failed refresh rejects and cannot overwrite a previously valid cache entry. Cache state is treated as deployment-scoped, is not expected to survive a deployment, and does not require serverless requests to reach the same process. Published reads bypass Sanity's CDN so a future narrow tag invalidation cannot refill from a stale Sanity edge.

Request APIs are absent from the ordinary cache module. Tests also guard against `use cache: remote` and `unstable_cache`; a remote handler would require separate platform qualification.

Source selection is fail-closed:

- local development/builds may use the deterministic approved seed projections;
- repository CI opts into those fixtures explicitly;
- hosted Netlify candidates cannot select fixture mode;
- published mode requires a project and dataset, and every route build validates its required singleton;
- `siteSettings` is read by the root layout, so the candidate validates all four fixed documents rather than only the three route documents.

## Sanity failure-injection result

Commands and results:

```sh
SANITY_CONTENT_SOURCE=fixture pnpm validate:editorial
# PASS — schema, seed, and 17 Editorial delivery/model tests

SANITY_CONTENT_SOURCE=fixture pnpm test:unit
# PASS — 12 files, 55 tests

SANITY_CONTENT_SOURCE=fixture pnpm build
# PASS — Home, Product, Synth, Checkout Preview, and not-found prerendered
# with Revalidate 30d / Expire 1y

env -u SANITY_STUDIO_PROJECT_ID -u SANITY_STUDIO_DATASET \
  SANITY_CONTENT_SOURCE=published pnpm build
# EXPECTED FAIL — missing SANITY_STUDIO_PROJECT_ID during prerender

pnpm seed:editorial
# PASS — uploaded the four social images and seeded four validated singletons

rm -rf .next && pnpm build
# PASS — clean build read and rendered the published Sanity projections
```

The focused integration test first obtains valid Home output, injects a Sanity timeout for the next fill, and confirms the fill rejects without creating fallback Editorial data. A separate malformed-response injection confirms invalid output rejects before cache admission. Together with the `max` Cache Component scope, this preserves the last valid public result during background runtime refresh while ensuring a clean deployment cannot be created from absent or invalid content.

The configured published Sanity dataset was seeded and read successfully by a clean local production build. This proves the adapter, projection, validation, and build-time composition path against published content. No Netlify candidate was deployed, so deployed availability, invalidation freshness, and platform cache behavior remain candidate-environment qualification; this report does not claim that later Acceptance evidence.
